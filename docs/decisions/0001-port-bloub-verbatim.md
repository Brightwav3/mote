# ADR 0001: Bloub's geometry is ported verbatim and pinned by tests, not reimplemented

- **Status:** Accepted
- **Date:** 2026-08-19
- **Decision owners:** Project owner

## Context

Mote draws a creature whose face and silhouette vocabulary comes from Bloub
(MIT, © 2026 Jérémy Perret). Bloub's numbers are not arbitrary — the expression
poses were measured frame by frame off a reference video, and the shape
generators encode specific choices (64 angular samples, corners rounded by
Minkowski sum with a disc, capsule and droplet built from the convex hull of two
circles, normalisation on peak radius).

The first implementation treated Bloub as an influence and rewrote the geometry
from the same ideas. Every part of that drifted, and the drift was invisible in
review because each piece looked plausible in isolation:

- shapes were sampled at 240 angles instead of 64, corners rounded with a p-norm
  soft minimum instead of a Minkowski sum, capsule and droplet built as stacks of
  overlapping circles instead of hulls — losing the straight tangent flanks that
  give them their character — and normalised on area, a rule invented here;
- expressions were reduced to a single mirrored eye pair, discarding the
  per-eye asymmetry that distinguishes `mefiant`, `confus` and `curieux`;
- head pose was paraphrased: `yaw` dropped entirely, `roll` and `pitch` applied
  at two thirds and a half strength. `neutre` is specified at
  (28.49, 28.62, -13) and was being drawn at (0, 0, 0).

The user's report was "your formes are just wrong" and "the faces are some weird
amalgamations". They were right in both cases, and neither was detectable from
the code alone — only by comparing against the source.

## Decision

Geometry that exists in Bloub is **ported**, function for function and constant
for constant, and pinned by tests that compare against independently
re-derived reference values. Divergence is a test failure, not a judgement call.

Where Mote adds something Bloub does not have — the `round` face — it is marked
as original at the definition site and excluded from the fidelity assertions.

The port carries its licence with it: `LICENSE-BLOUB` holds the upstream MIT
text and `NOTICE` names every ported file and what it came from.

## Rejected alternatives

**Reimplement from the same principles.** Tried first; this ADR exists because
it failed. The failure mode is specific and worth naming: a reimplementation of
a *measured* artefact has no error signal. Every individual choice looks
defensible, the result is wrong, and nothing in the code says so.

**Depend on Bloub as an npm package.** Bloub is a Vue application, not a library;
it exports no geometry API, and Mote ships as one self-contained HTML file with
no runtime dependencies (ADR 0002). A build-time dependency that had to be
tree-shaken out of a Vue app to reach four pure functions is more coupling for
less benefit.

**Vendor Bloub's TypeScript sources directly into `src/`.** Closest to correct,
and rejected only because Mote's sources are plain scripts concatenated by the
build (ADR 0002) and adding a TypeScript toolchain for four files is not worth
it. The port keeps the same function names and structure so a diff against
upstream stays legible.

**Copy the numbers by hand.** How the first errors got in. The tables in
`src/faces/expressions.js` were generated by parsing
`bloub/src/bot/expressions.ts` rather than retyped.

## Consequences

### Positive

- Fidelity is asserted, not asserted-to. `test/shapes.test.mjs` reproduces every
  generator independently and compares all 64 radii of all 8 shapes;
  `test/expressions.test.mjs` checks all 16 poses field by field.
- A future agent that "improves" a constant gets a red test naming the file it
  came from.
- The licensing position is explicit and correct rather than a credit line.

### Costs

- Upstream fixes do not arrive automatically; the port must be re-synced by
  hand, and nothing detects that upstream moved.
- The reference values are duplicated in the tests. That duplication is the
  point — a test that imported the same constants it checks would pass on any
  value.

## Enforced in

- `src/faces/expressions.js`
- `src/lib/geometry.js`
- `src/bodies/shapes.js`
- `src/bodies/palette.js`
- `test/shapes.test.mjs`
- `test/expressions.test.mjs`
- `NOTICE`

## Explicit non-decisions

This does not say Mote's *behaviour* should follow Bloub. The affect model,
attention, temperament and episode system are original and deliberately unlike
Bloub, which has no behaviour layer at all.

It does not authorise porting further Bloub code without extending `NOTICE` in
the same commit.

It does not decide what happens if Bloub relicenses or the upstream numbers
change; that is a fresh decision when it happens.
